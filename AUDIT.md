### Fonts

**No font is bundled and no font is declared.** Verified:

- `pubspec.yaml` has **no** `flutter: fonts:` section. It has `uses-material-design: true` and
  `generate: true`, nothing else under `flutter:`.
- No `google_fonts` dependency.
- Zero occurrences of `fontFamily`, `GoogleFonts`, or a custom `TextTheme` anywhere in `lib/`.
- No `assets/` folder exists; no `.ttf`/`.otf`/`.woff*` file exists anywhere in the repo.

So the app renders in the **platform default** — Roboto on Android, SF Pro on iOS — via Material 3
defaults. Weights the app actually asks for: `w700` (home title), `w800` (splash wordmark, glass bar
titles), plus Material defaults. Letter-spacing `-0.4` on the splash wordmark.

**However** — `cflogos/Course Forge Logo.dc.html` and `cflogos/Course Forge Splash.dc.html` (the logo
design exploration, in Hungarian) both load **Space Grotesk, weights 500 / 600 / 700** from Google
Fonts and set the wordmark in it at `font-weight: 700; letter-spacing: -0.02em`.

→ **`UNKNOWN — needs confirmation`: which typeface should the website use?** The app gives me no
answer. Space Grotesk is the only typeface anyone has ever chosen for CourseForge branding, so it is
my recommendation for headings; see open question 1.

## 1c. The downloadable course file format

Source of truth: `lib/features/saved_courses/data/course_file_service.dart` (131 lines — the whole
format lives there).

| Question | Answer |
|---|---|
| **File extension** | `.courseforge` — `const courseForgeFileExtension = 'courseforge'` (`course_file_service.dart:7`). No dot in the constant; used as `'$baseName.$courseForgeFileExtension'` |
| **MIME type declared by the app** | **None.** No MIME type is declared anywhere — not in the manifest, not in `Info.plist`, not in Dart. The import picker uses `FileType.custom` + `allowedExtensions: ['courseforge']`, which matches on extension, not MIME. Export hands the file to `SharePlus`, which infers a type from the extension and will land on `application/octet-stream` for an unknown one. → **`UNKNOWN — needs confirmation`**, see open question 3 |
| **Format** | **UTF-8 JSON**, pretty-printed with a 2-space indent (`JsonEncoder.withIndent('  ')`). Not zipped, not binary, no wrapper. Human-readable and diffable |
| **Top-level schema** | `format` (string, always `"courseforge.course"`), `formatVersion` (int, currently `1`), `exportedAt` (ISO-8601 UTC string), `course` (object) — full field list below |
| **Android handler registration?** | **No.** `android/app/src/main/AndroidManifest.xml` declares exactly one `intent-filter`: `MAIN` / `LAUNCHER`. There is no `VIEW`, no `SEND`, no `mimeType`, no `pathPattern`, no `scheme`. Tapping a `.courseforge` file on Android will not offer CourseForge |
| **…on iOS?** | **No.** `ios/Runner/Info.plist` has no `CFBundleDocumentTypes`, no `UTExportedTypeDeclarations`, no `UTImportedTypeDeclarations`, no `LSSupportsOpeningDocumentsInPlace`, no `CFBundleURLTypes`. iOS does not know the type exists |
| **Universal links / App Links configured?** | **No.** No `.entitlements` file exists in `ios/` at all (so no `com.apple.developer.associated-domains`). No `android:autoVerify` and no `assetlinks` reference anywhere in `android/`. Zero deep-link plumbing |
| **Does anything in a course file identify a device or user?** | **No device or user identity.** Details below |

### What the exported file actually contains

`course` object, in encoder order:

| Field | Type | Notes |
|---|---|---|
| `name` | string | User-authored. Validated on import: non-empty, ≤ 120 chars |
| `arenaWidthMeters` | double | Validated `> 0` on import; the creation form limits to 10–300 |
| `arenaLengthMeters` | double | as above |
| `surfaceType` | string enum | `sand` \| `grass` \| `indoorFooting` \| `custom` |
| `surfaceColorValue` | int | ARGB as a 32-bit integer (e.g. `4292396187` = `#FFD8C49B`). Decoder falls back to `0xFFE3C995` |
| `strideMode` | string enum | `horse` \| `pony` \| `custom`. Always `horse` in practice — see 1d |
| `customStrideMeters` | double? | Always `null` in practice |
| `elements` | array | The arena objects — schema below |
| `measurements` | array | `{id, startX, startY, endX, endY}` in meters |
| `routeDefinition` | object | The riding order and route — schema below |

`elements[]` (`course_models.dart:140`): `id`, `type` (one of 25 enum names), `xMeters`, `yMeters`,
`widthMeters`, `depthMeters`, `rotationDegrees`, `layerIndex`, `label` (string?),
`combinationElementCount`, `combinationElementTypes` (array of 3 type names, always written even for
non-combinations), `combinationFirstDistanceMeters`, `combinationSecondDistanceMeters`.

`routeDefinition` (`course_route_definition.dart:318`): `id`, `courseId`, `steps[]`, `routeVisible`,
`generationSettings{}` (11 numeric/bool tuning values), `manualControlPoints[]`, `isManuallyEdited`,
`modifiedAt` (ISO-8601 UTC), `schemaVersion`.
`steps[]`: `id`, `type` (`start`|`jump`|`finish`), `courseElementId`, `sequenceIndex`,
`obstacleNumber`, `combinationLetter`, `jumpDirection` (`forward`|`reverse`),
`includeInDistanceCalculation`, `connectionType` (`normal`|`relatedLine`|`combination`|`manual`),
`labelOffsetMeters{x,y}`, `numberSide` (`left`|`middle`|`right`).

All geometry is in **meters**, arena origin top-left, +x right, +y down, positive rotation clockwise.

### Privacy of the format — verified field by field

- No device identifier, no advertising ID, no installation ID, no account, no email, no locale, no
  settings, no file paths. `previewPath` (the local PNG preview) exists in the SQLite row but is
  **not** part of the export map.
- The identifiers that *are* present — `elements[].id`, `measurements[].id`, `routeDefinition.id`,
  `routeDefinition.courseId`, `steps[].id` — are locally generated **UUID v4** (`const Uuid().v4()`,
  random, not device-derived) or literal strings like `route-<courseId>`.
- `exportedAt` and `routeDefinition.modifiedAt` are wall-clock UTC timestamps. They reveal *when* a
  file was exported/edited — the only metadata leak, and a mild one.
- `name` is free text the user typed, so it can of course contain whatever they put there.

**Conclusion for the privacy policy: a `.courseforge` file published on the website is
geometry plus a name plus two timestamps. Nothing links it to a device, an install, or a person.**

### Import and export paths in the app

- **Export** (`editor_screen.dart:2334`): Export sheet → three formats: `courseforge` (this file),
  `pdf` (A4, auto landscape when the arena is wider than long), `png`. Written to the OS temp dir
  under `exports/`, filename sanitised to `[A-Za-z0-9_-]+`, then handed to the system share sheet via
  `SharePlus.instance.share`. **There is no "save to Downloads/Files" path — only share.**
- **Import** (`saved_courses_screen.dart:186`): Saved courses → Import course → `FilePicker.pickFiles`
  filtered to the `courseforge` extension → 5 MB size cap → `CourseFileService.decode` →
  `importCourse` under a **fresh UUID** → opens the editor. Decode rejects anything whose `format`
  isn't `"courseforge.course"` or whose `formatVersion` is missing / `< 1` / `> 1`.

So a rider downloading a course from the website today has to: save the file, open CourseForge, and
use Import. That is the workflow the site must document until the association files are wired up.

### Features that are actually implemented

Verified against the screens, painters, services and tests that exist — not against the README.

**Arena and course setup**
- Create a course with a name and arena width × length in meters, validated to **10–300 m**
  (defaults 50 × 60 in the form).
- Four surface colours (sand `#D8C49B` default, grass, pale, slate) and a surface type
  (sand / grass / indoor footing / custom).

**Object library and placement** (`element_catalog.dart`, 25 element types in 4 categories)
- *Jumps*: vertical, oxer, triple bar, combination, cross rail, wall, gate, Liverpool, Liverpool
  vertical, Liverpool oxer, open water, cavaletti.
- *Course markers*: start, finish.
- *Decorations*: flower box, flowers, bush, tree, cone, flag.
- *Arena objects*: obstacle number, judge booth, entrance, exit, in/out.
- Obstacles default to **3.0 m wide**; width is user-adjustable. Realistic default depths per type
  (oxer 1.4 m, triple bar 1.8 m, open water 3.5 m, Liverpool 2.0 m, cavaletti 0.4 m).
- Library cards preview each object using the same top-down vector renderer as the arena.
- Place, move (one-finger drag), rotate (handle), duplicate, delete, and reorder layers.
- Combinations of 2 or 3 elements with individually chosen element types and per-gap distances.

**Canvas**
- Modeless interaction: tap to select, one finger to drag, two fingers to pan/pinch-zoom anchored
  under the focal point. Fit-to-arena. Adaptive grid.
- Rotated hit testing from the top layer down.

**Precision tools**
- Optional snapping: 1 m grid, arena centre, object centre, 15° angles, parallel, perpendicular —
  with temporary guides.
- Alignment to arena edges/centres, or to a second selected object (same X, same Y, same rotation,
  parallel, perpendicular).
- Two-point measurement in meters, persisted as measurement lines; jump-to-jump measurements use
  obstacle logical centres.

**Course order and route**
- Tap-to-build riding order with automatic numbering, a reorderable sequence panel, explicit reuse
  of an obstacle, forward/reverse direction per jump, A/B/C combination letters, number side
  (rider's left / centre / right), and label offsets.
- Deleting a numbered obstacle warns first and repairs the numbering.
- Generated suggested route: oriented pre-start, approach/centre/landing anchors per jump, and
  post-finish, with straight protected crossings joined by cubic Bézier transitions; rendered as a
  dashed line with direction arrows; estimated route length from pure-Dart sampling.
- Manual curve editing: select a route transition, choose 0–N "curve dots" (waypoints), and drag
  them freely. *(This is Route Phase E, which `TASKS.md` still lists as unchecked — the code is
  there and wired to undo/redo and autosave.)*
- Stride estimate for distances ≤ 31 m using calibrated ranges (3 strides 13.5–15.0 m, 4 strides
  17.0–18.5 m, 5 strides 20.5–22.5 m, 6 strides 23.5–26.0 m, 7 strides 27.0–30.0 m), labelled as an
  estimate; outside those ranges it falls back to `round(distance / 4 m)`.

**Materials estimate**
- Live stand and pole count per course (`course_material_estimator.dart`): vertical 2 stands / 1–2
  poles, oxer 4 / 2–3, triple bar 6 / 3–4, cross rail 2 / 2, cavaletti 0 / 1, wall and gate 2 / 0.

**Reliability**
- Bounded **50-step** undo/redo, one history entry per completed gesture.
- **750 ms** debounced autosave, explicit manual save, and an immediate recovery save on app
  lifecycle change.
- PNG arena preview generated on save and shown on the saved-course cards.

**Saved courses**
- List with previews and "updated" dates, rename, duplicate, swipe-to-delete with confirmation,
  import.

**Export / share**

**Settings**
